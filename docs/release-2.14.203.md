# JKCREW 2.14.203

Riders opening the app together no longer need the leaderboard, park crown or saved-time history to finish before Daily Tricks can appear. Training waits for the authorized current sheet, progress and active timer. Optional Home requests are staggered and cancelled before starting if the rider has already navigated to training. Score and saved-time placeholders remain unknown until verified.

The client owns one bounded retry policy for safe reads. Timed-out profile, access and ranking reads use AbortSignal before retrying, with jitter instead of synchronized retries. SDK retries are disabled. Point writes are not automatically retried. Home, training and point feedback request only rider IDs and scores; the full Board retains its richer display. These changes preserve account approval, rider-access checks and account-scoped caches.

The database calculates authorized leaderboard scores in grouped passes instead of repeating seven rollups and retired progression lookups for every rider. Public signatures, team boundaries, ghost visibility, fractions, ranks and historical return fields remain compatible. An actual 35-rider before/after comparison matched all sixteen return columns. Full leaderboard JSON serialization fell from approximately 399 ms to 67 ms in the measured rollback comparison; its original 1.12 MB payload also explains why summary screens now omit avatars.

Point receipts and progress remain atomic and immediately available to live leaderboard and park-crown reads. Auxiliary chat, rank-push snapshots and crown announcements now use a private queue processed in bounded batches after commit. Failed batches retain their jobs for retry; captured job IDs prevent new arrivals from being deleted. Repeated completed weekly taps serialize on their own assignment and return without rewriting progress, landing history or attempts when the exact point receipt already exists. Missing-receipt repair, pause and undo behavior remain covered. Empty or deduplicated push batches no longer launch unnecessary Edge workers; due reminder requeues still wake the worker immediately.

Assignment-action prechecks use one private, authenticated lookup instead of repeatedly expanding the assignment, profile and parent-link policies. Both canonical rider and coach team boundaries remain required. Pending coaches, unrelated riders and foreign teams remain denied. The scoring implementation retains its independent own-rider or linked-coach authorization.

The 15-rider browser regression uses the actual application and bundled SDK, separate identities, a six-request backend queue and 80 ms simulated API latency. It tests fresh sign-in and saved-session bursts while optional statistics stay unavailable through the training actions. Before the change, none of the fifteen Daily screens opened until optional services recovered. Afterward, all fifteen opened their sheets, started timers and saved exactly one correct partial tick before statistics recovered, with no invented points or identity leaks. The strengthened suite passed 230 checks on two consecutive diagnostic runs. An earlier run had two interaction wait timeouts that were not reproduced; fifteen browser contexts on one computer give variable timings. This is a synthetic-backend regression, not a production capacity or response-time guarantee.

Separately, two successful hosted capacity runs used fifteen independent HTTPS clients and fifteen isolated test riders per run against the actual Auth and Data APIs. Each run completed 376 requests with no HTTP or optional-read errors: fresh sign-in, real refresh-token grants, restored-session reads, Daily timer creation, a positive two-point One Bang save, and an idempotent repeated tap all passed for all fifteen riders. Receipt, total-score and attempt checks confirmed that repeated taps minted no extra points or attempts. The controlled fixture has ten Daily assignments, one weekly assignment and limited history per rider. It does not simulate shared skatepark Wi-Fi or guarantee a fixed startup time; restored-session readiness varied up to approximately seventeen seconds. [Validation and cleanup details](performance/startup-capacity-validation-2026-11-18.md) link both sanitized request reports. Test accounts and fixture helpers were removed; real scoring and training data match their original hashes. The background worker has bounded, seven-day run-history retention.

UCI world rankings and World Cup overall standings are separate views for both men and women. Lars's verified publication shows world rank 13 with 2,610 points and World Cup overall rank 10 with 1,180 points. The Home card retains the world ranking and shows the World Cup position separately. Each view labels its own official source and publication date.

The public UCI importer validates all ranking pages, distinct rider identities and publication dates. World rankings update as a complete men's/women's pair. World Cup tables update as their own complete pair; an unavailable secondary source retains the last verified tables with an explicit stale status rather than holding back world rankings. The existing daily refresh job now imports both sets, covering weekly publication and delayed releases. These checks do not invent a new ranking date: an official UCI release must exist before a new ranking can be displayed.
